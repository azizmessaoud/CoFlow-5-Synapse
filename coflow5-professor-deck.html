Stage 2 · Define

The problem, stated human-centred

✗ Wrong (company-centric)

"We need to reduce average vehicle delay by 15% with five AI agents."

A team wish — exactly the framing Design Thinking warns against.

✓ Right (human-centric)

Urban traffic control is broken when it optimises vehicle throughput and treats people as interchangeable delay. Eight people need a system that sees them, protects them, and explains itself — and stays correct for one second if the radio or the LLM dies.

POV statements — user · need · because

SCAMPER highlights on the classic traffic light

Substitute: fixed-time as fallback · Combine: pedestrians + transit in one specialist (A3) · Adapt: Max-Pressure as watchdog · Modify: rewards count eco proxies · Put to other use: reason codes for trust · Eliminate: unlimited priority — every request bounded · Reverse: the person already on the crossing outranks the ambulance — yes (FR-A4)

The chosen design · role-decomposed hierarchy

System architecture — personas to actuation

Three rules: ① safety first — an in-crossing person finishes · ② boss is boss — only A1 pushes TraCI · ③ backup plans — dead radio → local A1; dead policy → ladder.

Five specialists. One set of hands on the lights.

Stages 1–3, in one breath

① Empathize

Eight personas; 33-row verified evidence trail (wait 2×, TAG 0.4, −7%/min ALS, TRR 1727 externality, SCATS audit, school exposure, incident share); claim flags block folklore numbers.

② Define

Not "cut delay 15%." POV: control that only sees cars fails people. HMW: agents and data for every person — and for the second the radio dies.

③ Ideate

Brainstorm → Worst Possible Idea → SCAMPER → six architectures. Chosen: five agents + message bus + safety layer + LLM explainer only.

Next: Prototype & Test — Step 0 pins SUMO and runs the classical baselines with no learned agent. Tier 0 answers the first falsifiable question: can a learned A1 honestly beat Max-Pressure? If the answer is no, that negative result is a finding, not a failure.
